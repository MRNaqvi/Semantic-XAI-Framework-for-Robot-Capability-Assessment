# Demo Section Draft

## Demonstration of the S-XAI Framework

This demonstration presents a human-centric Semantic Explainable Artificial Intelligence (S-XAI) framework for assessing robot suitability and operational capability in a manufacturing task. The system combines neural network prediction, ontology-based knowledge representation, Datalog reasoning, graph-based explanation, local neural explanation, natural language generation, and system-level logging in a single interactive interface. The objective of the demonstration is to show how a user can submit a new Cartesian task, obtain robot capability predictions, update a knowledge graph, inspect the resulting symbolic reasoning process, and generate explanations at different levels of abstraction.

The demonstration is organized around three interface views. Figure 1 presents the Main page, where the user configures the knowledge assets and runs the robot capability prediction. Figure 2 presents the Explanations page, where the user inspects reasoned facts, semantic graphs, counterfactual simulations, neural XAI outputs, natural language explanations, ontology structure, Datalog rules, and SPARQL queries. Figure 3 presents the System Logs page, which records the execution trace of the application and supports debugging, reproducibility, and transparency.

### Main Page: Task Input, Asset Loading, and Capability Prediction

Figure 1 shows the Main page of the S-XAI framework. This page is the entry point for the demonstration and provides the operational workflow for a new manufacturing task. The interface uses the default `S-XAI` datastore and loads three types of knowledge assets: the Robot Capability Ontology, Manufacturing Commonsense Knowledge Rules, and neural network models trained for the Ned-2 Niryo, ABB IRB 1200, and ABB IRB 2400 robots. The ontology provides the semantic vocabulary for robots, operational capabilities, measurements, and predicates such as `RCO:hasCapability` and `RCO:has_Measurement_Value`. The Datalog rules define the rule-based decision mechanism used to compare robot capability values. The Keras models estimate robot repeatability and precision for a new task.

The Main page also supports user-controlled asset replacement. The user can upload an OWL/RDF ontology, a Datalog rule file, or replacement Keras models. The ontology and Datalog uploads are sent to the RDFox-backed knowledge graph through the .NET API, while the Keras models are sent to the Flask model service. The `Reload Defaults` button restores the bundled ontology, rules, and model configuration, allowing the demonstration to return to a known baseline state.

The task input area asks the user to enter Cartesian coordinates in the form `X, Y, Z`. Roll, pitch, and yaw are intentionally excluded from this demonstration because the current repeatability and precision assessment is based only on Cartesian position. After the user clicks `Execute`, the coordinates are sent to the Flask API, which evaluates the Keras models for the three robots. The result dialog then displays the predicted repeatability and precision values for IRB 1200, IRB 2400, and Ned-2. Each value is identified as a neural network model prediction.

The user can either accept the predicted values or open the `Simulated Value` panel to enter hypothetical values. This enables counterfactual simulation: the user can test how a different repeatability or precision value would affect the downstream symbolic reasoning result. When the user clicks `Submit`, the latest predicted or simulated values are written to the knowledge graph as `RCO:has_Measurement_Value`. Old measurement values are deleted and replaced with the new values, ensuring that each execution reflects the current task. RDFox then applies the Datalog rules to infer robot suitability facts from the updated graph.

### Explanations Page: Semantic, Neural, and Natural Language Explanation

Figure 2 shows the Explanations page. This page is the central explanation workspace of the framework. It allows the user to inspect the results of the rule-based decision mechanism and connect them back to the neural predictions and knowledge graph evidence.

The `Reasoned Facts` view lists the suitability facts inferred by RDFox after the capability values are updated. These facts include conclusions such as best suitable robot due to repeatability, best suitable robot due to precision, least suitable robot due to repeatability, least suitable robot due to precision, and optimal robot. Each fact can be selected for graph-based inspection or natural language explanation.

The `Graph` view visualizes the semantic explanation of a selected fact. In the selected fact mode, the graph shows the robot instance, relevant operational capability nodes, measurement value nodes, RDF predicates, and the selected reasoned fact. Properties such as `RCO:hasCapability` and `RCO:has_Measurement_Value` are represented as labeled edges, because they describe relationships between graph entities. The whole graph mode displays a broader representation of the current knowledge graph state, including robots, capabilities, measurements, and reasoned facts. Graph filters allow the user to show or hide robots, capabilities, measurement values, reasoned facts, or restrict the view to the selected robot. The graph can also be exported as SVG or PNG.

The `Simulated / Counterfactual Comparison` view compares the baseline reasoning result with the result obtained after user simulation. The before state represents the facts inferred from the neural network predictions, while the after state represents the facts inferred after the user enters hypothetical values. This view explains how changes in repeatability or precision can modify robot suitability conclusions. It therefore supports interactive what-if analysis over the semantic decision mechanism.

The `XAI` view provides neural explanation for the model predictions that feed the knowledge graph. The user can run LIME, SHAP, Integrated Gradients, and Permutation Importance. LIME explains the local behavior of the neural model around the current Cartesian point using feature weights for `X`, `Y`, and `Z`. SHAP attributes the current prediction across the same coordinates. Integrated Gradients estimates contribution from a baseline point to the current task point, and Permutation Importance measures output sensitivity when one coordinate is perturbed at a time. The selected fact contribution panel links a semantic conclusion to the most relevant neural influence, allowing the user to understand how the neural component contributed to the symbolic reasoning result.

The `Natural Language Explanations` view generates a textual explanation of the selected reasoned fact. The interface supports OpenAI and local Ollama-based explanation, while Mistral and Gemini are included as planned provider options. For OpenAI, the user can paste an API key for the current browser session. For Ollama, the explanation is generated locally using an open model. The generated explanation summarizes the selected fact, the relevant robot, the capability focus, the current repeatability and precision values, and the Datalog rule mechanism that produced the conclusion. The purpose is not to state that the reasoner itself makes a subjective decision, but to explain formally that the rule-based decision mechanism identifies a robot by comparing operational capability values according to the loaded Datalog rules.

The Explanations page also includes an Ontology Viewer, a Rule Viewer, and a SPARQL query viewer. The Ontology Viewer lets the user inspect classes, subclass relations, instances, properties, and ontology predicates as an interactive graph. The Rule Viewer displays the active Datalog rules exactly as loaded from the source file. The SPARQL viewer shows both the reasoned facts query and the latest knowledge graph update query. Together, these views expose the semantic structure, rule logic, and query-level operations behind the demonstration.

### System Logs Page: Traceability and Reproducibility

Figure 3 shows the System Logs page. This page records the operational trace of the demonstration and provides transparency over the interaction between the browser interface, Flask model service, .NET API, and RDFox knowledge graph. The log entries are timestamped and displayed in reverse chronological order, with the most recent event at the top.

The log records successful and failed operations across the complete workflow. Asset-related events include default ontology and rule reloads, custom ontology upload, custom Datalog rule upload, and Keras model upload. Prediction-related events include neural model execution for a specific `X, Y, Z` task, prediction failures, knowledge graph updates, and fact refreshes. Explanation-related events include LIME, SHAP, Integrated Gradients, Permutation Importance, OpenAI explanations, Ollama explanations, ontology viewer loading, and rule viewer loading.

The System Logs page is useful for demonstration, debugging, and reproducibility. For example, a normal successful run should show that the default knowledge assets were loaded, the neural prediction was completed, the operational capability values were updated in the knowledge graph, and RDFox facts were refreshed. If an error occurs, the logs help identify whether the issue comes from Flask prediction, RDFox update, SPARQL querying, missing Python dependencies, invalid OpenAI credentials, or unavailable Ollama models. The `Clear Log` button removes only the visible browser log and does not modify the knowledge graph, uploaded assets, prediction results, or explanations.

### Demonstration Workflow

The complete demonstration proceeds as follows. First, the user opens the Main page shown in Figure 1 and verifies that the default ontology, Datalog rules, and Keras models are loaded. The user enters a new Cartesian task as `X, Y, Z` and executes the neural models. The system predicts repeatability and precision values for the three robots. The user may accept the predictions or enter hypothetical simulated values. After submission, the values are written to the knowledge graph as `RCO:has_Measurement_Value`, and RDFox applies the Datalog rules to infer suitability facts.

Second, the user opens the Explanations page shown in Figure 2. The user can inspect the inferred facts, select a fact, view its semantic graph, compare baseline and simulated reasoning states, run neural XAI methods, generate a natural language explanation, inspect the ontology, inspect the active Datalog rules, and examine the SPARQL queries used by the system. This connects the data-driven neural prediction layer with the symbolic knowledge graph and rule-based reasoning layer.

Third, the user opens the System Logs page shown in Figure 3. The logs provide an execution history of the demonstration, showing which assets were loaded, which predictions were executed, whether the knowledge graph was updated, which facts were refreshed, and which explanation methods were run. This final view supports traceability and helps verify that the demonstration was executed correctly.

Overall, the demo illustrates how neural prediction and semantic reasoning can be integrated in a human-centric explanation workflow. The neural models estimate robot operational capabilities for a new Cartesian task, the knowledge graph stores these values using the Robot Capability Ontology, Datalog rules derive suitability facts, and the interface presents multiple explanation modalities, including graph-based explanation, counterfactual simulation, neural feature attribution, natural language explanation, ontology inspection, rule inspection, SPARQL transparency, and system logs.
